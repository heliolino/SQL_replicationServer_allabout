⚡ Setup quick reference — the whole build, one command per line

Transactional replication from zero to verified, as a cheat sheet: every command in order, one line on what it does, and a link to the page that explains it properly. Replace names in 'quotes'. Before you start: work through the prerequisites checklist once.

run at DISTRIBUTOR Phase 1 — configure the distributor

CommandWhat it does
EXEC sp_adddistributor @distributor = N'DIST01', @password = N'<link pwd>'; Declares this instance a distributor and sets the admin link password publishers will use — details
EXEC sp_adddistributiondb @database = N'distribution'; Creates the distribution database: the queue, agent history, and error store — details
EXEC sp_adddistpublisher @publisher = N'PUB01', @distribution_db = N'distribution', @working_directory = N'\\DIST01\ReplData'; Authorizes PUB01 to use this distributor and sets the snapshot folder (must be a UNC share for remote agents) — details

run at PUBLISHER Phase 2 — attach the publisher & enable the database

CommandWhat it does
EXEC sp_adddistributor @distributor = N'DIST01', @password = N'<link pwd>'; Points the publisher at the remote distributor — the password must match phase 1 — details
EXEC sp_get_distributor; Sanity check: installed = 1 and the right distributor name before going further — details
EXEC sp_replicationdboption @dbname = N'SalesDB', @optname = N'publish', @value = N'true'; Marks the database as publishable (creates the replication system objects in it) — details
USE SalesDB; EXEC sp_addlogreader_agent @job_login = N'<domain\acct>', @job_password = N'<pwd>'; Creates the Log Reader Agent job that will harvest committed transactions from the log — details

run at PUBLISHER Phase 3 — create the publication and add articles

CommandWhat it does
EXEC sp_addpublication @publication = N'SalesPub', @repl_freq = N'continuous', @independent_agent = N'true'; Creates a transactional publication with its own dedicated Distribution Agent — details
EXEC sp_addpublication_snapshot @publication = N'SalesPub', @job_login = N'<domain\acct>', @job_password = N'<pwd>'; Creates the Snapshot Agent job that will generate the initial .bcp/.sch files — details
EXEC sp_addarticle @publication = N'SalesPub', @article = N'Orders', @source_owner = N'dbo', @source_object = N'Orders'; Adds one table to the publication (repeat per table; filters and options here) — details
EXEC sp_grant_publication_access @publication = N'SalesPub', @login = N'<agent login>'; Lets the agent login read the publication — forgetting this is a classic first-run failure — details

run at PUBLISHER Phase 4 — create the subscription and initialize

CommandWhat it does
EXEC sp_addsubscription @publication = N'SalesPub', @subscriber = N'SUB01', @destination_db = N'SalesReporting', @subscription_type = N'Push', @sync_type = N'automatic'; Registers the subscriber; automatic means the snapshot will initialize it — details
EXEC sp_addpushsubscription_agent @publication = N'SalesPub', @subscriber = N'SUB01', @subscriber_db = N'SalesReporting', @job_login = N'<domain\acct>', @job_password = N'<pwd>'; Creates the Distribution Agent job that pushes commands to this subscriber — details
EXEC sp_startpublication_snapshot @publication = N'SalesPub'; Runs the Snapshot Agent now: generates the snapshot the Distribution Agent then applies — details

run anywhere stated Phase 5 — verify it works

CommandWhat it does
EXEC distribution..sp_replmonitorhelpsubscription @publisher = N'PUB01', @publication_type = 0; dist Per-subscription status and latency rollup — status 5/6 means retrying/failed — details
USE SalesDB; EXEC sp_posttracertoken @publication = N'SalesPub'; pub Injects a latency probe that timestamps each hop of the pipeline — details
EXEC sp_replcounters; pub Pending transaction count and latency per published database, straight from the publisher — details
SELECT COUNT(*) FROM dbo.Orders; pub sub Row counts on both sides should match once the queue drains — details
☁ Doing this on Azure SQL Managed Instance? Four deltas
  • @working_directory must be an Azure file share in a storage account (\\acct.file.core.windows.net\share) plus @storage_connection_string with the account key.
  • Agent jobs run under managed accounts: pass @job_login = NULL, @job_password = NULL and use SQL authentication logins for the publisher/subscriber connections.
  • Prefer push subscriptions; pull isn't supported when the distributor is an MI and the subscriber isn't.
  • Initializing from backup works differently — Microsoft owns the backup chain, so use PITR + initialize from lsn (or COPY_ONLY to URL when TDE allows).
