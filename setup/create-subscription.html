Step 3 — Create the Subscription

Connects a subscriber to the publication and creates the delivery agent. Affects: Subscriber (subscription DB + metadata), Publisher (subscription registration), Agents (Distribution/Merge Agent job), and Distributor (MSsubscriptions rows).

Decide first: push or pull?

This decides where the agent job lives and where you troubleshoot. Comparison table on the Subscriber page. Default to push for a handful of always-on servers, pull for many or occasionally-connected subscribers.

Option A — SSMS wizard (New Subscription)

  1. Publisher → Local Publications → right-click the publication → New Subscriptions…
  2. Distribution Agent Location: "Run all agents at the Distributor" (push) or "Run each agent at its Subscriber" (pull).
  3. Subscribers: add the subscriber instance; pick or create the destination database (the wizard can create an empty one).
  4. Distribution Agent Security: process account + connection accounts (needs db_owner in the subscription DB, read on the snapshot share, PAL membership). The weakest point of most installs — don't rush it.
  5. Synchronization Schedule: "Run continuously" (typical for transactional) or scheduled (typical for merge/pull over WAN).
  6. Initialize Subscriptions: "Immediately" (delivers the snapshot as soon as one exists) or "At first synchronization". For initialize-from-backup scenarios untick and handle manually.
  7. Finish + generate script.

Option B — T-SQL, push subscription

USE SalesDB;
EXEC sp_addsubscription
     @publication = N'SalesPub',
     @subscriber = N'SUB01',
     @destination_db = N'SalesReporting',
     @subscription_type = N'Push',
     @sync_type = N'automatic',        -- snapshot-based initialization
     @article = N'all',
     @update_mode = N'read only';

EXEC sp_addpushsubscription_agent
     @publication = N'SalesPub',
     @subscriber = N'SUB01',
     @subscriber_db = N'SalesReporting',
     @job_login = N'DOMAIN\replDistrib', @job_password = N'***',
     @subscriber_security_mode = 1,    -- Windows auth to the subscriber
     @frequency_type = 64;             -- 64 = start continuously with SQL Agent

Option B′ — T-SQL, pull subscription

-- 1. at the PUBLISHER: register the pull subscription
USE SalesDB;
EXEC sp_addsubscription
     @publication = N'SalesPub',
     @subscriber = N'SUB01', @destination_db = N'SalesReporting',
     @subscription_type = N'pull', @sync_type = N'automatic';

-- 2. at the SUBSCRIBER: create the pull side + its agent job
USE SalesReporting;
EXEC sp_addpullsubscription
     @publisher = N'PUB01', @publisher_db = N'SalesDB',
     @publication = N'SalesPub';

EXEC sp_addpullsubscription_agent
     @publisher = N'PUB01', @publisher_db = N'SalesDB',
     @publication = N'SalesPub',
     @distributor = N'DIST01',
     @job_login = N'DOMAIN\replPull', @job_password = N'***',
     @distributor_security_mode = 1,
     @frequency_type = 64;

Watch the first delivery

-- distribution agent sessions & messages
SELECT TOP 20 h.start_time, h.duration, h.comments, h.delivered_commands, h.current_delivery_rate
FROM distribution.dbo.MSdistribution_history h
JOIN distribution.dbo.MSdistribution_agents a ON a.id = h.agent_id
WHERE a.subscriber_db = N'SalesReporting'
ORDER BY h.start_time DESC;

-- or just: Replication Monitor → publication → subscription → View Details
  1. "Delivering replicated snapshot" — bulk insert phase; subscriber tables are being dropped/recreated (⚠ apps on the subscriber see missing objects now).
  2. "Delivered snapshot" → "No replicated transactions are available" — initialized and idle. Healthy continuous agents cycle this message.
  3. Run an INSERT at the publisher and verify it lands at the subscriber within seconds; then post a tracer token for a measured baseline.
⚠ Subscription hygiene rules
  • Dropping a subscription needs cleanup on both sides (sp_dropsubscription at the publisher, sp_droppullsubscription at the subscriber); orphans later block re-creation — fix with sp_subscription_cleanup.
  • Never restore an old backup over a subscription database "to fix it" — its LSN watermark (MSreplication_subscriptions) will no longer match the distributor's queue. Reinitialize instead.
  • Record every subscription's push/pull mode, agent account, and schedule in your CMDB — during an incident you won't have time to rediscover where the agent job lives.
