Step 1 — Configure the Distributor

Everything else depends on this step: it creates the distribution database, binds the publisher to its distributor, sets the snapshot folder, and installs the cleanup jobs. Affects: Distributor and the Publisher↔Distributor link.

☁ On Azure SQL Managed Instance

Same procs, two extra rules: @working_directory must be an Azure file share in a storage account (\\acct.file.core.windows.net\share — backslashes only) and sp_adddistpublisher also takes @storage_connection_string with the storage account key. Open outbound TCP 445 to the storage endpoint, use SQL authentication, and keep the distributor MI at a version equal to or above the publisher. Publisher and distributor must be both in Azure or both on-premises — never split. Full walkthrough: MI-to-MI setup.

Option A — SSMS wizard

  1. Connect to the distributor instance in SSMS (often the publisher itself for a local distributor). Right-click Replication → Configure Distribution…. If you don't see a Replication node, the feature isn't installed — back to prerequisites.
  2. Distributor page: choose "<this server> will act as its own Distributor" (local) or "Use the following server" (remote — the remote side must already be configured as a distributor and have a password set for the link).
  3. Snapshot folder: enter the UNC path (\\DIST01\ReplData). The wizard warns about local paths — take the warning seriously; pull subscriptions cannot read local paths.
  4. Distribution database page: name (keep distribution unless hosting multiple), and data/log file locations — put them on proper storage, not the system drive.
  5. Publishers page: tick the publishers allowed to use this distributor. For a remote distributor, set the administrative link password here (you'll need it again on the publisher side).
  6. Finish, or better: choose Generate script so the configuration is in source control. Verify afterwards with the queries below.

Option B — pure T-SQL

-- 1. make this instance a distributor
USE master;
EXEC sp_adddistributor
     @distributor = @@SERVERNAME,          -- local distributor
     @password = N'StrongPassword!1';      -- distributor_admin link password

-- 2. create the distribution database
EXEC sp_adddistributiondb
     @database = N'distribution',
     @data_folder = N'D:\SQLData',
     @log_folder  = N'E:\SQLLogs',
     @min_distretention = 0,               -- hours
     @max_distretention = 72,              -- hours: commands kept after delivery
     @history_retention = 48,              -- hours of agent history
     @security_mode = 1;                   -- Windows auth

-- 3. register the publisher and its snapshot folder
EXEC sp_adddistpublisher
     @publisher = @@SERVERNAME,            -- or 'PUB01' for a remote publisher
     @distribution_db = N'distribution',
     @working_directory = N'\\DIST01\ReplData',
     @security_mode = 1;

For a remote distributor: run steps 1–3 at the distributor (with @publisher='PUB01'), then at the publisher run sp_adddistributor @distributor='DIST01', @password='StrongPassword!1' to join it.

Verify

EXEC sp_get_distributor;        -- installed? distribution db? remote?
EXEC sp_helpdistributor;        -- full details incl. working directory
EXEC sp_helpdistributiondb;     -- retention settings
EXEC sp_helpdistpublisher;      -- registered publishers

-- the jobs that should now exist on the distributor
SELECT name FROM msdb.dbo.sysjobs
WHERE name LIKE 'Distribution clean up%'
   OR name LIKE 'Agent history clean up%'
   OR name LIKE 'Expired subscription clean up%'
   OR name LIKE 'Replication agents checkup%';
