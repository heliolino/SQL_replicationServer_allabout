What is replication?

SQL Server replication is a set of technologies for copying and distributing data and database objects from one database to another and keeping them synchronized. Unlike backup/restore it is continuous and granular: you publish individual tables (or subsets of rows and columns), and changes flow automatically to one or many destination servers.

It is built around a publishing-industry metaphor with three server roles:

  • Publisher — the source server. It makes data available as publications composed of articles (tables, views, procedures).
  • Distributor — the middleman. It stores replication metadata and, for transactional replication, queues every change in its distribution database until all subscribers have received it.
  • Subscriber — the destination server(s). Each holds a subscription to a publication, delivered by Agents as either push (agent runs at the distributor) or pull (agent runs at the subscriber).

⚠ Deprecation status — set expectations correctly

Snapshot, transactional, and merge replication remain fully supported in SQL Server 2022 and 2025. Only updatable transactional subscriptions (immediate/queued updating) and some Oracle publishing scenarios are deprecated. Azure SQL Database can be a subscriber (push) to transactional/snapshot publications; Azure SQL Managed Instance supports publisher, distributor, and subscriber roles.

How a change travels (transactional replication)

  1. Application commits a transaction at the Publisher. Rows in published tables are marked for replication in the transaction log.
  2. Log Reader Agent scans the log, converts committed changes into commands, and writes them to the distribution database (sp_replcmds under the hood). Only then may the log records be truncated.
  3. Distribution database queues the commands in MSrepl_commands / MSrepl_transactions until every subscriber has them (or retention expires).
  4. Distribution Agent reads pending commands and applies them to each Subscriber in commit order, calling auto-generated procedures like sp_MSins_dboTableName.
  5. Cleanup jobs at the Distributor delete delivered commands past the retention window.

The vocabulary you must speak

TermMeaning
ArticleA single replicated object: a table (optionally filtered by rows/columns), view, indexed view, stored procedure, or UDF.
PublicationA named group of articles from one database — the unit a subscriber subscribes to.
SubscriptionA request by a subscriber for a publication; push (agent at distributor) or pull (agent at subscriber).
Initialization / snapshotThe initial copy of schema + data that brings a subscriber to the starting state. Re-doing it is reinitialization.
RetentionHow long the distributor keeps commands (default max 72 h for distribution retention) and how long a subscription may stay un-synced before expiring (default 336 h).
LatencyTime from commit at publisher to apply at subscriber. Measured precisely with tracer tokens.
ReinitializationMarking a subscription to receive a fresh snapshot — the fix of last resort, and the cost you're trying to avoid in most incidents.
Agent profileA named set of agent parameters (timeouts, batch sizes, error handling) stored at the distributor.
