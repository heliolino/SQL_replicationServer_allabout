Reinitialization — the big hammer, used precisely

-- one subscription
EXEC sp_reinitsubscription
     @publication = N'SalesPub',
     @article = N'all',
     @subscriber = N'SUB01', @destination_db = N'SalesReporting',
     @invalidate_snapshot = 1;    -- 1 = also generate a fresh snapshot

-- then start the snapshot agent (unless a valid snapshot exists)
EXEC sp_startpublication_snapshot @publication = N'SalesPub';

-- merge flavor (adds @upload_first: push unsent subscriber changes up before reinit?)
EXEC sp_reinitmergesubscription
     @publication = N'FieldSalesPub',
     @subscriber = N'DEV-LAPTOP-07', @subscriber_db = N'FieldSales',
     @upload_first = N'true';
🛑 Reinit checklist before you run it
  • Subscriber tables will be dropped/truncated per article @pre_creation_cmd — warn the application owner.
  • Subscriber-side extras (indexes, triggers, permissions on those tables) vanish with drop — have their scripts ready.
  • For merge with unsynced subscriber changes: decide @upload_first consciously — false discards those changes forever.
  • Estimate snapshot generation + delivery time; a reinit during business hours can be a bigger outage than the original incident.

Dropping subscriptions — clean path and orphan path

-- PUSH: at the publisher
EXEC sp_dropsubscription
     @publication = N'SalesPub', @article = N'all',
     @subscriber = N'SUB01', @destination_db = N'SalesReporting';

-- PULL: both sides
--   at the publisher:
EXEC sp_dropsubscription @publication = N'SalesPub', @article = N'all',
     @subscriber = N'SUB01', @destination_db = N'SalesReporting';
--   at the subscriber:
EXEC sp_droppullsubscription
     @publisher = N'PUB01', @publisher_db = N'SalesDB', @publication = N'SalesPub';

-- subscriber still thinks it's subscribed but publisher has no record (or vice versa):
-- at the SUBSCRIBER, per orphaned subscription:
EXEC sp_subscription_cleanup
     @publisher = N'PUB01', @publisher_db = N'SalesDB', @publication = N'SalesPub';

-- nuclear local cleanup at the subscriber (all replication metadata in the DB):
EXEC sp_removedbreplication @dbname = N'SalesReporting';

-- publisher-side force-drop ignoring an unreachable distributor:
EXEC sp_dropsubscription @publication = N'SalesPub', @article = N'all',
     @subscriber = N'SUB01', @destination_db = N'SalesReporting',
     @ignore_distributor = 1;      -- ☠ leaves distributor metadata; clean there too

Subscriber-side inspection

-- transactional subscriptions known locally + their LSN bookmark
SELECT publisher, publisher_db, publication, distribution_agent,
       transaction_timestamp
FROM dbo.MSreplication_subscriptions;

-- the auto-generated apply procs (= initialized as a subscriber)
SELECT name FROM sys.procedures
WHERE name LIKE 'sp[_]MSins[_]%' OR name LIKE 'sp[_]MSupd[_]%' OR name LIKE 'sp[_]MSdel[_]%';

-- merge: what's tracked locally
SELECT TOP 10 * FROM dbo.MSmerge_genhistory ORDER BY coldate DESC;
SELECT COUNT(*) FROM dbo.MSmerge_contents;      -- change backlog
SELECT COUNT(*) FROM dbo.MSmerge_tombstone;     -- delete backlog

Identity ranges (merge / auto range management)

-- current allocations
SELECT * FROM MSmerge_identity_range_allocations ORDER BY time_of_allocation DESC;

-- force a new range for the publisher (ranges for subscribers refresh at sync):
EXEC sp_adjustpublisheridentityrange @publication = N'FieldSalesPub';

-- check the enforcing constraint on the table
SELECT name, definition FROM sys.check_constraints
WHERE parent_object_id = OBJECT_ID('dbo.Orders') AND name LIKE 'repl_identity_range%';
