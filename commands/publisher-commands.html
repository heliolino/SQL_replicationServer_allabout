Publisher commands

Commands that create, alter, inspect, or destroy publisher-side objects — publications, articles, filters — and the log-pipeline internals that live in the publication database.

Lifecycle

sp_replicationdboption — the master switch

EXEC sp_replicationdboption
     @dbname  = N'SalesDB',
     @optname = N'publish',        -- or 'merge publish', 'subscribe', 'sync with backup'
     @value   = N'true';
  • Enabling publish starts log-record marking immediately; disabling it requires all publications in the DB to be dropped first.
  • sync with backup on publication + distribution DBs = restore-consistent replication (latency cost).

sp_addpublication — parameters that matter later

EXEC sp_addpublication
     @publication      = N'SalesPub',
     @repl_freq        = N'continuous',   -- 'continuous' = transactional; 'snapshot' = snapshot type
     @sync_method      = N'concurrent',   -- concurrent = minimal-lock snapshot (transactional)
     @retention        = 336,             -- hours until an unsynced subscription expires
     @immediate_sync   = N'false',        -- true = keep snapshot+cmds for full retention (DB bloat!)
     @allow_anonymous  = N'false',        -- forces immediate_sync when true
     @independent_agent= N'true',         -- own distribution agent per subscription
     @replicate_ddl    = 1,               -- ALTERs flow to subscribers
     @enabled_for_p2p  = N'false',
     @status           = N'active';

sp_addarticle — per-table control

EXEC sp_addarticle
     @publication      = N'SalesPub',
     @article          = N'Orders',
     @source_owner     = N'dbo',
     @source_object    = N'Orders',
     @destination_table= N'Orders',           -- may differ!
     @destination_owner= N'rpt',              -- may differ!
     @type             = N'logbased',         -- or 'proc exec' / 'serializable proc exec'
     @pre_creation_cmd = N'drop',             -- drop | delete | truncate | none
     @schema_option    = 0x000000000803509F,  -- bitmask: what schema ships
     @identityrangemanagementoption = N'manual',  -- or 'auto' (merge-style ranges)
     @ins_cmd = N'CALL sp_MSins_dboOrders',
     @upd_cmd = N'SCALL sp_MSupd_dboOrders',  -- SCALL = only changed columns
     @del_cmd = N'CALL sp_MSdel_dboOrders';
⚠ @schema_option bits support engineers actually meet
  • 0x01 generate object creation script · 0x10 clustered index · 0x40 nonclustered indexes
  • 0x08 replicate timestamp columns as-is · 0x20 convert UDTs to base types
  • 0x100 user triggers · 0x200 FKs · 0x1000 column collation
  • Changing schema_option on a live article ⇒ requires a new snapshot for the article.

Filters

-- row filter (static, transactional)
EXEC sp_articlefilter @publication = N'SalesPub', @article = N'Orders',
     @filter_name = N'FLT_Orders', @filter_clause = N'Region = N''EU''';
EXEC sp_articleview  @publication = N'SalesPub', @article = N'Orders',
     @view_name = N'VW_Orders',  @filter_clause = N'Region = N''EU''';

-- column filter: start from none, add back
EXEC sp_articlecolumn @publication = N'SalesPub', @article = N'Orders';            -- all columns
EXEC sp_articlecolumn @publication = N'SalesPub', @article = N'Orders',
     @column = N'CardNumber', @operation = N'drop', @force_invalidate_snapshot = 1; -- remove one

Changing and dropping

-- most property changes invalidate the snapshot; the procs make you say so:
EXEC sp_changepublication @publication = N'SalesPub',
     @property = N'retention', @value = N'504',          -- hours
     @force_invalidate_snapshot = 0, @force_reinit_subscription = 0;

EXEC sp_droparticle     @publication = N'SalesPub', @article = N'Orders',
     @force_invalidate_snapshot = 1;
EXEC sp_droppublication @publication = N'SalesPub';

The two @force_* flags are honesty checks: if the proc refuses without them, the change will cost a snapshot or a reinit — know that before you force.

Teardown of last resort

-- strips every trace of replication metadata from the DB, no questions asked.
-- Use when normal drops fail with orphaned-metadata errors. Local effect only:
-- distributor/subscriber sides must be cleaned separately.
EXEC sp_removedbreplication @dbname = N'SalesDB';
