Distributor commands

Distribution database administration, retention control, queue inspection, and the monitor procs — the support engineer's main console.

Setup & configuration

-- declare / inspect / remove the distributor role
EXEC sp_adddistributor @distributor = @@SERVERNAME, @password = N'***';
EXEC sp_get_distributor;                        -- is this box a distributor? which DB?
EXEC sp_helpdistributor;                        -- full config incl. snapshot working directory
EXEC sp_dropdistributor @no_checks = 0;         -- @no_checks=1 forces past orphans (☠ last resort)

-- the distribution database itself
EXEC sp_adddistributiondb @database = N'distribution',
     @max_distretention = 72, @history_retention = 48, @security_mode = 1;
EXEC sp_helpdistributiondb;

-- retention changes (applies from next cleanup run)
EXEC sp_changedistributiondb @database = N'distribution',
     @property = N'max_distretention', @value = N'96';
EXEC sp_changedistributiondb @database = N'distribution',
     @property = N'history_retention', @value = N'72';

-- publishers allowed to use this distributor
EXEC sp_adddistpublisher @publisher = N'PUB01', @distribution_db = N'distribution',
     @working_directory = N'\\DIST01\ReplData', @security_mode = 1;
EXEC sp_helpdistpublisher;
EXEC sp_changedistpublisher @publisher = N'PUB01',
     @property = N'working_directory', @value = N'\\DIST01\ReplData2';
⚠ Retention changes are a two-edged tool

Raising max_distretention buys subscribers more offline runway but grows MSrepl_commands. Lowering it below the time any subscriber lags marks that subscription for reinitialization. Change deliberately, during calm, with queue depth in front of you.

Queue inspection — the incident toolkit

USE distribution;

-- decode what's queued (THE stuck-command tool)
EXEC sp_browsereplcmds
     @xact_seqno_start = '0x0000002B000001D8000A',   -- from MSrepl_errors / agent error text
     @xact_seqno_end   = '0x0000002B000001D8000A',
     @publisher_database_id = 1;                      -- MSrepl_transactions.publisher_database_id
-- output column 'command': {CALL [sp_MSins_dboOrders] (...)} — the exact failing statement

-- queue depth / largest transactions / pending per subscription:
SELECT COUNT(*) FROM dbo.MSrepl_commands WITH (NOLOCK);
EXEC sp_replmonitorsubscriptionpendingcmds
     @publisher = N'PUB01', @publisher_db = N'SalesDB', @publication = N'SalesPub',
     @subscriber = N'SUB01', @subscriber_db = N'SalesReporting', @subscription_type = 0;

-- full error text when job history is truncated
SELECT TOP 20 time, CONVERT(nvarchar(4000), error_text) AS error_text
FROM dbo.MSrepl_errors ORDER BY time DESC;

Cleanup machinery

-- what the 'Distribution clean up: distribution' job actually runs:
EXEC distribution.dbo.sp_MSdistribution_cleanup
     @min_distretention = 0, @max_distretention = 72;

-- history trim ('Agent history clean up' job):
EXEC distribution.dbo.sp_MShistory_cleanup @history_retention = 48;

-- expired subscriptions ('Expired subscription clean up' job, runs in each pub DB):
EXEC sp_expired_subscription_cleanup;
  • Running cleanup manually with a bigger batch window (off-hours) is a legitimate way to drain a bloated queue — monitor blocking while it runs.
  • Cleanup deletes only commands delivered to all subscriptions (or expired ones) — if the queue won't shrink, find the subscription holding the watermark: SELECT agent_id, MIN(transaction_timestamp) FROM dbo.MSsubscriptions ... or simply the Replication Monitor pending-commands view per subscription.

Agent profile management (stored at the distributor)

EXEC sp_help_agent_profile;                             -- all profiles (agent_type 1,2,3,4,9)
EXEC sp_help_agent_parameter @profile_id = 2;           -- parameters of one profile

EXEC sp_add_agent_profile @profile_name = N'CatchUp-Distribution',
     @agent_type = 3, @profile_type = 0,
     @description = N'Temporary catch-up profile';
-- then sp_add_agent_parameter per parameter, and assign via Replication Monitor
-- or update MSdistribution_agents.profile_id (documented but low-level).

Danger zone

CommandWhy it's here
sp_dropdistributor @no_checks = 1, @ignore_distributor = 1Forces distributor removal leaving orphaned metadata on publishers/subscribers — only for rebuilding a box that is already beyond repair
Manual DELETE FROM MSrepl_commandsNever. Breaks watermark consistency; use cleanup procs/retention instead
Shrinking the distribution DB during business hoursBlocks agents; if you must reclaim space after a bloat incident, do it in a window
