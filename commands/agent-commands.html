Agent jobs & executables

The anatomy of a replication agent job, the command-line parameters of each executable, and the job-control commands a support engineer uses daily.

☁ On Azure SQL Managed Instance

Jobs and job-control commands are the same, with three deltas: agents run under managed accounts (@job_login = NULL — there is no Windows service account to rotate), credential rotation means changing the SQL authentication passwords via the sp_change*_agent procs, and the -Output <file> verbose-logging parameter has no local disk to write to — use the history tables and MSrepl_errors for diagnostics instead. Details: MI setup page.

Anatomy of an agent job

Every agent job has three steps — knowing them explains the job history you read:

  1. "Replication agent startup message" — logs the start (sp_MSadd_repl_commands… infra).
  2. "Run agent." — the real step: runs the executable with its parameter string. This is where you temporarily add -Output … -OutputVerboseLevel 2 for deep debugging.
  3. "Detect nonlogged agent shutdown." — runs if step 2 dies without logging a stop; writes the "The replication agent has not logged a progress message in 10 minutes" style heartbeat errors.
-- inventory by category
SELECT j.name, c.name AS category, j.enabled
FROM msdb.dbo.sysjobs j
JOIN msdb.dbo.syscategories c ON c.category_id = j.category_id
WHERE c.name LIKE 'REPL-%' ORDER BY c.name, j.name;

-- start/stop (same as Replication Monitor's Start/Stop Synchronizing)
EXEC msdb.dbo.sp_start_job @job_name = N'PUB01-SalesDB-SalesPub-SUB01-1';
EXEC msdb.dbo.sp_stop_job  @job_name = N'PUB01-SalesDB-SalesPub-SUB01-1';

-- read the parameter string of the Run agent step
SELECT js.command
FROM msdb.dbo.sysjobsteps js
JOIN msdb.dbo.sysjobs j ON j.job_id = js.job_id
WHERE j.name = N'PUB01-SalesDB-SalesPub-SUB01-1' AND js.step_id = 2;

Executable parameter reference

logread.exe — Log Reader

-Publisher [PUB01] -PublisherDB [SalesDB] -Distributor [PUB01]
-DistributorSecurityMode 1 -Continuous
-- tuning: -ReadBatchSize 500  -PollingInterval 5  -MaxCmdsInTran 0
--         -LogScanThreshold 500000  -QueryTimeout 1800

distrib.exe — Distribution Agent

-Publisher [PUB01] -PublisherDB [SalesDB] -Publication [SalesPub]
-Distributor [PUB01] -SubscriptionType 0
-Subscriber [SUB01] -SubscriberDB [SalesReporting] -SubscriberSecurityMode 1 -Continuous
-- tuning:  -CommitBatchSize 100  -CommitBatchThreshold 1000
--          -SubscriptionStreams 1  -QueryTimeout 1800  -LoginTimeout 15
-- danger:  -SkipErrors 2601:2627:20598   (hides divergence — stopgap only)
-- debug:   -Output C:\Temp\distrib.log -OutputVerboseLevel 2

snapshot.exe — Snapshot Agent

-Publisher [PUB01] -PublisherDB [SalesDB] -Publication [SalesPub] -Distributor [PUB01]
-- tuning: -BcpBatchSize 100000  -MaxBcpThreads 1  -70Subscribers (legacy compat)

replmerg.exe — Merge Agent

-Publisher [PUB01] -PublisherDB [FieldSales] -Publication [FieldSalesPub]
-Subscriber [DEV-LAPTOP-07] -SubscriberDB [FieldSales] -Distributor [PUB01]
-- tuning:  -ExchangeType 3 (1 upload only, 2 download only, 3 both)
--          -UploadGenerationsPerBatch 100  -DownloadGenerationsPerBatch 100
--          -Validate 3 (rowcount+checksum after sync)
--          -SrcThreads 4 -DestThreads 4

Credential rotation runbook (the password-change incident)

  1. Identify affected agents: which jobs run under / connect as the rotated account? (job step command strings + sp_helpdistpublisher, agent security pages.)
  2. Update per agent type: 
    -- log reader (run in the publication DB)
EXEC sp_changelogreader_agent @job_login = N'DOMAIN\replLogReader', @job_password = N'NewPass!';

-- snapshot agent
EXEC sp_changepublication_snapshot @publication = N'SalesPub',
     @job_login = N'DOMAIN\replSnapshot', @job_password = N'NewPass!';

-- push distribution agent
EXEC sp_changepushsubscription_agent
     @publication = N'SalesPub', @subscriber = N'SUB01', @subscriber_db = N'SalesReporting',
     @job_login = N'DOMAIN\replDistrib', @job_password = N'NewPass!';

-- pull distribution agent (at the subscriber)
EXEC sp_changepullsubscription_agent
     @publisher = N'PUB01', @publisher_db = N'SalesDB', @publication = N'SalesPub',
     @job_login = N'DOMAIN\replPull', @job_password = N'NewPass!';
  3. Restart the agents (stop/start jobs) and verify one clean session per agent in history.
  4. Post a tracer token to confirm end-to-end flow.
⚠ Don't edit job step strings by hand for security changes

The sp_change*_agent procs update both the job and the replication metadata; hand-editing the job step leaves metadata stale and the next wizard/script regeneration silently reverts your fix.
