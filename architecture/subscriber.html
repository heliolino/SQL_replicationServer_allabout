Subscriber — where the data lands

The Subscriber receives the publication into a subscription database. The big design fork is push vs. pull — it decides where the Distribution/Merge Agent runs, where its logs are, and where you look when delivery stops.

command delivery Pull + local snapshot path = the classic "access denied" trap (⚠ on the pull agent)

Push vs. pull — decision table

What initialization puts into the subscription database

  • The article tables themselves (schema per @schema_option, data via BCP).
  • Auto-generated apply procedures per article: sp_MSins_dboOrders, sp_MSupd_dboOrders, sp_MSdel_dboOrders — the Distribution Agent calls these instead of raw DML.
  • MSreplication_subscriptions — the subscription's bookmark (last applied transaction_timestamp).
  • For merge: MSmerge_contents, MSmerge_tombstone, MSmerge_genhistory, triggers on every article, and a rowguid column.
-- what subscriptions exist here (transactional pull/push)?
USE SalesReporting;
SELECT publisher, publisher_db, publication, distribution_agent,
       transaction_timestamp              -- last applied LSN watermark
FROM dbo.MSreplication_subscriptions;

-- is the agent currently connected and applying?
SELECT s.session_id, s.login_name, s.program_name, r.status, r.wait_type, r.blocking_session_id
FROM sys.dm_exec_sessions s
LEFT JOIN sys.dm_exec_requests r ON r.session_id = s.session_id
WHERE s.program_name LIKE '%distrib%' OR s.program_name LIKE '%replmerg%';

Rules of the road for subscriber data

🛑 In one-way topologies, the subscriber is read-only by contract — not by enforcement

Nothing technically prevents writes to subscriber tables in snapshot/transactional replication, but any local UPDATE/DELETE on replicated rows sets up a future error 20598 (row not found) or 2627 (PK violation) when the publisher's version of events arrives. If local writes are required, the design should have been merge, P2P, or separate local tables. As support: find the writer (DML trigger or Extended Events audit), don't just skip the error.

  • You may add extra indexes, extra tables, and even extra columns (with defaults) at the subscriber — common for reporting. Document them: they disappear on reinitialization if the article drops/recreates the table (@pre_creation_cmd = 'drop').
  • Subscriber triggers must be NOT FOR REPLICATION or convergence breaks.
  • Consider enabling READ_COMMITTED_SNAPSHOT so reporting readers don't block the Distribution Agent's writes.
